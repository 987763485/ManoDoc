## 1. 产品概述

### 1.1 一句话

DullDoc 是一个 **macOS 本地优先的文档 → Markdown 工作台**：把常见的可读文档转换成排版清晰、可直接使用的 Markdown；需要时，再把一批文档清洗、切块、补充元数据，产出厂商中立的语料包。转换层采用 **anydoc 快路径 + xberg 增强（OCR / 复杂表格 / 失败回退）+ PaddleOCR（P1 中文 OCR）+ pandoc 导出**。

### 1.2 背景与问题

1. **工具离散**：docx 用 Pandoc，PDF 用 Marker，Excel 靠脚本，导出又是另一套工具。
2. **被迫联网**：在线转换要先上传文件，内部标准、测评报告、合同与制度不可接受。
3. **排版丢失**：标题层级塌陷、表格错列、中文断行错乱、页眉页脚混入正文。
4. **批量化门槛**：处理一个文件夹需要拼命令、写循环、处理失败重试，非技术同事无法使用。
5. **语料化断层**：转完 Markdown 后，还要另写脚本做清洗、切块、元数据与入库。

### 1.3 目标用户

| 用户 | 特征 | 核心任务 | 成功标准 |
| --- | --- | --- | --- |
| 主要用户：知识工作者 | 安全合规、研究、法务、咨询、技术写作；长期处理标准/报告/手册 | 把 docx/PDF/xlsx 转成可直接使用的 Markdown，放入 Obsidian/语料库/LLM | 80% 的转换不再需要终端或浏览器 |
| 次要用户：不写代码的同事 | 需要拖拽、进度、失败原因 | 批量转换一个文件夹，拿到可交付的 Markdown | 不需要看命令行，失败知道为什么 |
| 高级用户：自动化使用者 | 需要可复现、可脚本化 | 预设、CLI、watch folder、manifest | 同输入 + 同预设 = 同产出 |

### 1.4 产品目标

1. **一站式**：在一个 App 内完成「转 → 洗 → 切 → 打包」。
2. **离线优先**：默认零网络请求，不登录、不上传、不埋点。
3. **保真优先**：标题层级、表格、列表、公式、图片位置尽量保留；宁可慢，不可错。
4. **可解释**：每个文件都能看到引擎、参数、警告与失败原因。
5. **可复现**：输入哈希、引擎版本、参数与结果写入 manifest。
6. **引擎分层**：anydoc 走快路径，xberg 处理扫描件/复杂表格与 anydoc 失败回退，PaddleOCR（P1）提供中文 OCR 增强，pandoc 负责导出；每份产物标明所用引擎与版本。

### 1.5 成功指标

| 指标 | 目标 |
| --- | --- |
| `example/` 测试集转换成功率 | 可读文本文件 100% |
| 50 页文本型 PDF 单文件转换耗时 | < 10 秒（Apple Silicon） |
| 批量 50 个文件稳定性 | 无崩溃；失败可定位到文件与原因 |
| 默认设置下的联网请求 | 0 次 |
| 同输入 + 同预设的 chunk 数 | 两次一致 |
| 日常转换不再打开终端/浏览器 | ≥ 80% |

### 1.6 非目标

- 不做 PDF 编辑、注释、表单、电子签名。
- 不做在线转换站、账号体系、云同步、团队协作。
- 不做向量库管理、检索问答 UI。
- 不追求 1000+ 长尾格式；主流 8 类格式做深。
- 不承诺所有复杂 PDF 表格一次转对；以质量分级与警告替代虚假承诺。

## 2. 范围与优先级

### 2.1 版本范围

| 范围 | 内容 | 优先级 |
| --- | --- | --- |
| MVP | 单文件转换、Markdown 预览、保存、pandoc 导出 HTML/DOCX/EPUB、批量队列、清洗、切块、元数据、语料包、历史、设置、日志、错误处理 | P0 |
| MVP | **xberg 第二内核**：扫描件/图片 PDF 的 OCR、复杂表格、anydoc 失败回退 | P0 |
| MVP+1 | Marker/MinerU 备选引擎、PaddleOCR 中文 OCR、PDF 输出、监听文件夹、CLI、引擎插件化、深色模式 | P1 |
| 后续 | Windows/Linux、Finder 快捷操作、平台直连、团队协作 | P2 |
| 不做 | PDF 编辑、在线服务、账号、向量库 UI、长尾格式军备竞赛 | — |

### 2.2 明确不做

1. 账号、云同步、云端转换、在线 OCR（除非用户显式开启未来的云服务）。
2. PDF 精修、复杂排版出版、公式所见即所得编辑。
3. 向量库管理、检索问答、Embedding 生成。
4. 插件市场与第三方脚本运行时。
5. 音频/视频转写。

### 3.3 关键页面流转

```
启动 → 转换（空状态：拖入文件）
  ├─ 单文件 → 转换 → 预览 → 保存 / 导出 → 历史新增
  ├─ 多文件/文件夹 → 批量（确认）→ 配置 → 队列 → 结果 → 历史新增
  └─ 历史 → 详情 → 重跑 / 打开输出

设置 → 引擎检测失败 → 引导安装 / 查看说明
转换 → PDF 预检发现无文本页 → 跳过确认 / 取消 / 查看原因
批量 → 失败文件 → 重试 / 跳过 / 查看错误
```

### 6.2 `chunks.jsonl`

| 字段 | 类型 | 必填 | 说明 |

| `metadata.source` | string | 是 | 源文件绝对路径（可配置脱敏） |

## 7. 引擎路由与 PDF 预检

### 7.1 路由表

| 输入 | 引擎 | 行为 |
| --- | --- | --- |
| doc/docx/ppt/pptx/xls/xlsx/odt/ods/odp/rtf/epub/csv | anydoc | 直接转换 |
| Markdown | 直通 | 仅清洗/切块，不重新解析 |
| HTML / MHTML | pandoc | HTML → Markdown；异常时提示 |
| 文本型 PDF | PDF 预检 → anydoc | 全部页面有文本时 anydoc；出现 `NeedsOcr` 或质量 C 时回退 xberg |
| 扫描件 / 图片 PDF | PDF 预检 → xberg | P0：xberg OCR；中文低置信度时 PaddleOCR（P1）；均不可用时进入跳过/失败策略 |
| 中文 OCR 增强 | PaddleOCR（P1） | 中文扫描件、低置信度页、用户显式选择时启用；输出文本/坐标/置信度 |
| 图片 | xberg / PaddleOCR | 输入支持为 P1；引擎能力已具备 |
| 加密文件 | anydoc → `Encrypted` | 提示密码（P1）或取消 |

### 7.2 PDF 预检算法

1. 逐页提取文本，统计非空白字符数。
2. `needs_ocr` 页：字符数 < 10。
3. 若 `needs_ocr` 为空：直接 anydoc。
4. 若 `needs_ocr` 非空且 xberg 可用：优先路由 xberg OCR（可整份或逐页），记录 `engine=xberg`、`ocr_pages`；若 xberg 置信度低且 PaddleOCR 可用（P1），可对低置信度页重跑 PaddleOCR；xberg 失败再进入步骤 5。
5. 若 xberg 不可用或 OCR 失败：若 PaddleOCR（P1）可用，优先路由 PaddleOCR；否则按以下策略处理：
   - 单文件：弹窗列出页码，默认「跳过并继续」，可取消；用户可勾选「本任务不再询问」。
   - 批量：按预设 `pdf_image_page_policy`：
     - `skip`（默认）：移除这些页生成临时 PDF 再转换；记录 `skipped_pages` 与警告。
     - `fail`：该文件失败，错误码 `E_PDF_IMAGE_PAGES`。
     - `ask`：暂停队列，等待用户处理。
   - 若 `needs_ocr` 页数 > 3 或占比 > 10%：默认按 `E_NEEDS_OCR` 失败，除非用户显式选择「强制跳过」。
6. 临时 PDF 只存在应用数据目录，任务结束删除。
7. manifest 记录 `skipped_pages`、`ocr_pages`、原始页数、转换页数与实际引擎。

### 7.3 表格质量分级

| 级别 | 条件 | 处理 |
| --- | --- | --- |
| A | GFM 表格列数一致、无合并单元格、单元格内容完整 | 直接输出 |
| B | 存在合并单元格/跨页/长文本，但结构可读 | 输出 GFM 或 HTML，附警告 |
| C | 列数错乱、内容明显串行、无法可靠还原 | 若 xberg 可用，自动以 xberg 重试；仍为 C 则输出最佳结果 + 明确警告，建议使用 PaddleOCR（P1）或 Marker |

### 8.1 状态清单

| 大文件 | 警告 | 预计耗时/内存；建议拆分 |
| 扫描件 | 预检结果 | 页码列表；跳过/取消/了解 OCR |

### 8.2 进度模型

- 任务级：总文件数、完成数、失败数、当前文件。
- 文件级：阶段（识别/解析/清洗/切块/写入）、百分比（可估算时）、耗时。
- 批量：可暂停调度（P1）、取消全部、重试失败。
- 所有长任务必须可取消；取消后清理临时文件。

## 9. 验收标准

### 9.1 功能验收（基于 `example/`）

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| AC-01 | `GB:T 28448-2019...docx` | 转换成功；标题 ≥ 40；表格 2 个；标题编号规范（`5.1`）；CJK 标题不被拆开 |
| AC-02 | `等级保护测评2.0要求指标清单v1.xlsx` | 转换成功；表格行数 ≈ 1048；表头完整 |
| AC-03 | `高风险判定...pdf`（原始） | xberg 或 PaddleOCR 可用时自动 OCR 第 1 页并转换成功；manifest 记录 `ocr_engine` 与 `ocr_pages: [1]`；均不可用时识别无文本页并走跳过策略 |
| AC-04 | 同上 PDF，xberg/PaddleOCR 均不可用且选择取消 | 任务取消；无输出文件；无残留临时文件 |
| AC-05 | `等保测评skill.md` → HTML/DOCX/EPUB | 三种导出成功；图片/表格/代码块正常 |
| AC-06 | 批量 50 个混合文件 | 无崩溃；失败文件有错误码与原因；报告可导出 |
| AC-07 | 勾选清洗 + 切块 + 元数据 | 生成 `chunks.jsonl` + `manifest.json`；JSONL 每行可解析；chunk 数稳定 |
| AC-08 | 断网 | 全流程可用；无网络请求 |
| AC-09 | 文件名含中文/空格/冒号/分号 | 正常转换与输出，不触发命令注入 |
| AC-10 | 输出目录已有同名文件 | 默认跳过并警告；覆盖/重命名策略正确 |
| AC-11 | 复杂表格 PDF | xberg 回退后表格质量 A/B，或给出 C 级警告；不得静默输出错乱表格 |
| AC-12 | xberg 未安装 / 模型缺失 | 界面给出安装说明；转换仍可按 anydoc + 跳过策略完成，或明确失败 |
| AC-13 | 中文扫描页 + PaddleOCR 已安装 | 识别成功；manifest 记录 `ocr_engine=paddleocr`；可与 xberg 结果对比 |
| AC-14 | PaddleOCR 未安装 | 默认 xberg；不阻塞转换；设置页给出安装说明 |

### 9.2 质量验收

1. 标题层级与原文一致；无「#」符号混入正文。
2. 中文正文无异常字间空格；英文单词间空格保留。
3. 表格为合法 GFM（每行列数一致）或明确降级为 HTML 并警告。
4. 页眉、页脚、页码不出现在正文（开启清洗时）。
5. 图片路径可移植；移动输出目录后仍可显示。
6. 每个失败文件都有错误码、原因与下一步。

### 9.3 非功能验收

- 文本 PDF 50 页 < 10s；docx < 2s；xberg OCR 50 页 < 120s；批量 50 文件 < 5 分钟。
- 批量 50 文件无崩溃；取消后无残留。
- 默认设置抓包 0 请求。
- 同输入 + 同预设两次 chunk 数一致。
- 主要流程可纯键盘完成；对比度 AA。

### 9.4 UI 验收

S5 高保真原型确认后，界面必须 100% 还原：颜色、背景、间距、字号、圆角、状态与交互。此条在 S5/S8 逐项验收。

## 10. 风险与依赖

| 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- |
| anydoc 对 PDF 页级失败 | 含封面/插图页的 PDF 不可用 | REQ-014/015/016 页级预检与策略 |
| anydoc 复杂表格保真 | 「排版清晰」承诺受限 | REQ-045 质量分级 + xberg 回退（REQ-098） |
| xberg 稳定性与模型依赖 | 项目刚更名，OCR/表格模型可能带来体积、平台差异与许可问题 | S6 用真实样本验证；P0 但不可行时可降级 P1（回退 anydoc + 跳过策略），需用户确认 |
| PaddleOCR 依赖与模型 | Python/Paddle 模型，macOS 上以 CPU 为主；体积与速度需评估 | P1 可选组件，引导安装；不进入 MVP 默认路径 |
| 中文清洗误伤 | 英文/代码/URL/公式被破坏 | REQ-044 分域规则 + 预览开关 |
| pandoc 为 GPL | 分发合规 | sidecar、许可证、源码获取说明 |
| pandoc 输出 PDF 依赖 LaTeX | 本机已验证失败 | REQ-091 P1 评估 Typst/WebView |
| Marker/MinerU 模型许可 | 商用受限 | S6 核对；默认用户自装，不随包分发 |
| macOS 签名/公证 | 分发复杂 | NFR-009；MVP 先本地运行 |
| Tauri WebView 差异 | 渲染/字体差异 | NFR-010；目标机型验证 |
| 大规模批量内存 | 大文件 OOM | REQ-033 并发与内存保护；流式处理 |

## 11. 待 `/grill-me` 辩驳的问题

1. **PDF 跳过策略**：xberg（P0）与 PaddleOCR（P1）已作为 OCR 路径；「跳过无文本页」是否只应作为两者均不可用时的降级路径，而不是默认行为？
2. **语料包是否属于 MVP**：用户已确认需要勾选清洗/切块/元数据，但它是否应排在单文件与批量之后，避免 MVP 过大？
3. **HTML/MHTML 输入**：是否 P0？anydoc 不支持 HTML，需要引入 pandoc 作为提取器，是否值得？
4. **历史存储**：JSON 是否足够？是否应直接上 SQLite，避免后续迁移？
5. **表格质量分级**：A/B/C 的判定规则是否可实现、可解释？是否会变成主观判断？
6. **中文清洗边界**：CJK 与数字/英文之间的空格规则，是否存在不可逆误伤？是否需要「只对标题/正文生效」的分域？
7. **PDF 输出**：是否应该在 MVP 就提供一个「WebView 打印为 PDF」的简单路径，而不是完全推到 P1？
8. **第二引擎落地**：xberg 已按 P0 纳入；S6 是否还需要用真实样本与 Marker/MinerU 做三方对比？若 xberg 体积/稳定性不达标，降级 P1 的判定标准是什么？xberg 的 OCR/表格模型是否允许随安装包分发？
9. **100% UI 还原**：macOS 原生控件（文件选择器、菜单、弹窗）如何定义「100% 还原」？是否只要求应用内页面 100%？
10. **加密文档**：MVP 是否需要密码输入？anydoc 返回 `Encrypted` 时，是否只提示「请先解密」即可？
11. **批量默认策略**：`skip` 是否会静默丢内容？是否应默认 `ask`，只在用户勾选「记住」后 skip？
12. **性能指标**：50 页 PDF < 10s 是否包括清洗/切块？批量 50 文件 < 5 分钟是否现实？
13. **PaddleOCR 边界**：PaddleOCR 与 xberg 内置 OCR 的职责如何划分？是否只在中文低置信度时启用？PP-Structure 是否用于表格？
